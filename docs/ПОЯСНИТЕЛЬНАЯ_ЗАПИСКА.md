# Пояснительная записка

**Проект:** «Электронный магазин цветов» (Flower Store)
**Дисциплина:** Модульное тестирование программного обеспечения

---

## 1. Общие сведения

Приложение представляет собой локально работающий интернет-магазин цветов и
готовых букетов. Покупатель может просматривать каталог, складывать товары в
корзину, оформлять заказ (без обязательной регистрации), зарегистрироваться и
видеть историю своих заказов. Администратор управляет товарами, категориями и
статусами заказов.

Технологический стек:

| Слой | Технологии |
|------|------------|
| Сервер | Java 17, Spring Boot 3.3.5, Spring MVC |
| Данные | Spring Data JPA, Hibernate, PostgreSQL |
| Представление | статические HTML-страницы + JavaScript, CSS (без серверных шаблонов и внешних фреймворков) |
| Тесты | JUnit 5, Mockito, AssertJ, Spring Boot Test, JaCoCo, H2 |

Архитектура — слоистая, сверху вниз:

```
static (HTML/JS)  →  controller  →  service  →  repository  →  PostgreSQL
                         ↘  model (сущности JPA)  ↗
```

* **controller** — разбирает HTTP-запросы, вызывает сервисы, формирует ответ
  (JSON для страниц или редирект для форм). Бизнес-правил не содержит.
* **service** — вся бизнес-логика: корзина, оформление заказа, статусы,
  каталог, пользователи. Здесь же и происходит модульное тестирование.
* **repository** — доступ к данным через Spring Data JPA.
* **model** — сущности JPA и перечисление `OrderStatus` с правилами переходов.

## 2. Структура базы данных

Схема создаётся автоматически Hibernate (`ddl-auto=update`), а также описана
в `src/main/resources/db/schema.sql` для ручного развёртывания.

| Таблица | Содержимое | Ключевые связи |
|---------|------------|----------------|
| `categories` | категории каталога | — |
| `users` | покупатели и администратор (`role`: `USER` / `ADMIN`) | — |
| `products` | цветы и букеты (цена, остаток, признак видимости) | `category_id → categories.id` |
| `orders` | заказы (данные покупателя, способ оплаты, статус, сумма, время) | `user_id → users.id` (NULL для гостя) |
| `order_item` | позиции заказа с копией названия и цены на момент покупки | `order_id → orders.id` |

Особенности:

* пароль хранится только в виде BCrypt-хеша (`password_hash`);
* позиция заказа хранит **снимок** названия и цены — изменение цены товара
  не переписывает уже оформленные заказы;
* список позиций загружается вместе с заказом (`@EntityGraph`), поэтому
  запрос к заказу не превращается в N+1 запросов.

## 3. Основные правила бизнес-логики

**Корзина** (`CartService`) лежит в HTTP-сессии как таблица
`id товара → количество`. При просмотре корзины она приводится в порядок:
товары, исчезнувшие из каталога, скрытые и закончившиеся — удаляются,
количество урезается до остатка на складе.

**Добавление товара** проверяет: количество больше нуля, товар существует и
виден, суммарное количество (в корзине + добавляемое) не превышает остаток.

**Оформление заказа** (`OrderService.create`) проверяет форму (имя, e-mail
**или** телефон, адрес, непустая корзина), пересчитывает сумму по актуальным
ценам, списывает остаток и создаёт позиции заказа со снимком цены.
Новый заказ получает статус `NEW`.

**Смена статуса** (`OrderService.changeStatus`) разрешает только переходы,
разрешённые `OrderStatus.canGo`:

| Из \ В | новый | в обработке | доставлен | отменён |
|--------|-------|-------------|-----------|----------|
| **новый** | — | ✅ | ❌ | ✅ |
| **в обработке** | ❌ | — | ✅ | ✅ |
| **доставлен** | ❌ | ❌ | — | ❌ |
| **отменён** | ❌ | ❌ | ❌ | — |

При отмене заказа товары возвращаются на склад.

**Каталог** (`CatalogService`) валидирует данные товара: название не пустое,
цена указана и неотрицательна (округляется до двух знаков), остаток указан и
неотрицателен, категория выбрана и существует. Ссылка на фото, если пуста,
сохраняется как `NULL`. Категорию с товарами удалить нельзя.

**Пользователи** (`AuthService`): при регистрации проверяются имя, формат
e-mail и длина пароля (не короче 6 символов), занятый e-mail отклоняется с
кодом 409. Пароль хранится в виде BCrypt-хеша. Права проверяются методом
`admin()`: нет входа — 401, обычный пользователь — 403.

Все ошибки бизнес-логики — один тип `ApiException` с HTTP-кодом
(400 / 401 / 403 / 404 / 409). `ErrorHandler` превращает их либо в JSON
(для `/api/...`), либо в редирект на нужную страницу с текстом ошибки в адресе.

## 4. Подход к тестированию

### 4.1. Принципы

1. **Отдельный класс тестов для каждого сервиса**, реализующего бизнес-логику:
   `CartServiceTest`, `OrderServiceTest`, `CatalogServiceTest`, `AuthServiceTest`.
2. **Тесты сервисного слоя не обращаются к базе.** Репозитории заменяются
   моками Mockito, сессия — мок `HttpSession`, который хранит атрибуты в
   обычной `Map` (`shop.support.TestFixtures`).
3. **Каждый тест проверяет один сценарий** и имеет понятное имя;
   сценарии сгруппированы вложенными классами `@Nested` с `@DisplayName`.
4. **Покрываются не только успешные, но и граничные и ошибочные пути**:
   пустые и отрицательные значения, отсутствующие записи, недостаточный
   остаток, недопустимые переходы статусов, недостаточные права.
5. Общая оснастка вынесена в `shop.support.TestFixtures`, чтобы тесты читались
   как сценарии, а не как настройка моков.

### 4.2. Уровни тестов

| Уровень | Аннотация | Что проверяет | База |
|---------|-----------|---------------|------|
| Модульный (сервисы) | — | бизнес-логика | нет (моки) |
| Модульный (модели, исключения) | — | переходы статусов, `ApiException`, обработчик ошибок | нет |
| Веб-слой | `@WebMvcTest` | маршруты, коды ответов, редиректы, разграничение доступа | нет (сервисы — заглушки) |
| Доступ к данным | `@DataJpaTest` | запросы репозиториев, `@EntityGraph`, связи таблиц | H2 в режиме PostgreSQL |
| Интеграционный | `@SpringBootTest` | контекст Spring, демо-данные | H2 |

Тесты полностью изолированы от рабочей базы `flowerstore`:
во время `mvn test` используется встроенная H2, адрес которой задан
в `src/test/resources/application.properties`.

### 4.3. Покрытие обязательных сценариев (ТЗ, п. 5.2)

| Обязательный сценарий | Тесты |
|------------------------|-------|
| Добавление товара в корзину — корректно | `CartServiceTest.Add.добавлениеТовараКладётЕгоВКорзину` |
| Добавление — больше, чем на складе | `CartServiceTest.Add.добавлениеБольшеОстаткаОтклоняется`, `добавлениеСПревышениемУжеДобавленногоОтклоняется` |
| Добавление — несуществующий товар | `CartServiceTest.Add.добавлениеНесуществующегоТовараОтклоняется` |
| Расчёт суммы — одна позиция | `CartServiceTest.Sums.суммаПоОднойПозиции`, `OrderServiceTest.Sums.суммаПоОднойПозиции` |
| Расчёт суммы — несколько позиций | `CartServiceTest.Sums.суммаПоНесколькимПозициям`, `OrderServiceTest.Sums.суммаПоНесколькимПозициям` |
| Расчёт суммы — пустая корзина | `CartServiceTest.Sums.пустаяКорзинаДаётНоль`, `OrderServiceTest.Sums.пустаяКорзинаНеСоздаётЗаказ` |
| Оформление заказа и списание остатка | `OrderServiceTest.Create.остатокСписываетсяСоСклада`, `уКаждойПозицииСписываетсяСвойОстаток` |
| Оформление — отказ при недостаточном остатке | `OrderServiceTest.Create.приНехваткеОстаткаЗаказНеСоздаётся` |
| Оформление — корректный начальный статус | `OrderServiceTest.Create.новыйЗаказПолучаетСтатусНовый` |
| Смена статуса — допустимые переходы | `OrderServiceTest.ChangeStatus.переходВОбработкуРазрешён`, `переходВДоставленРазрешён` |
| Смена статуса — недопустимый переход | `OrderServiceTest.ChangeStatus.переходИзДоставленВНовыйЗапрещён`, `переходНовыйВДоставленЗапрещён`, `переходВНовыйИзОбработкиЗапрещён` |
| Валидация товара — отрицательная цена | `CatalogServiceTest.Validation.отрицательнаяЦенаОтклоняется` |
| Валидация товара — пустое название | `CatalogServiceTest.Validation.пустоеНазваниеОтклоняется` |

### 4.5. Требования к окружению

Сборка и тесты выполняются на **JDK 17–23** (целевая версия — 17,
`maven.compiler.release=17`). Ограничение вызвано не кодом проекта, а составом
зависимостей: Byte Buddy, входящий в состав Mockito 5.11, официально
поддерживает Java до 23, а JaCoCo 0.8.12 — до Java 22. На более новой JDK
(например, Java 27) Mockito не может создавать моки, и тесты `@WebMvcTest`
падают с ошибкой:

```
Mockito cannot mock this class: class shop.service.AuthService
Caused by: IllegalArgumentException: Java 27 (71) is not supported by the current
version of Byte Buddy which officially supports Java 23 (67)
```

Чтобы комплект тестов не зависел от версии JDK, в `pom.xml` для surefire
задан системный параметр `net.bytebuddy.experimental=true`: с ним все 211
тестов проходят и на Java 27. Дополнительно из инструментации JaCoCo
исключены служебные классы, которые Mockito и Hibernate генерируют в рантайме
(`*$MockitoMock*`), — иначе агент печатает предупреждения о классах,
собранных в более новом формате.

Рекомендуемая конфигурация для чистого вывода и корректного отчёта о покрытии:
JDK 17 или 21 и в IntelliJ IDEA (*Project Structure → Project*, *Settings →
Build Tools → Maven → Runner*), и в командной строке (`JAVA_HOME`).

## 5. Выводы

* Приложение разделено на слои так, что бизнес-логика изолирована в сервисах
  и может быть проверена модульными тестами без базы данных и без контейнера.
* Разработан комплект из 211 автоматических тестов, покрывающий сервисный
  слой, модели, обработку ошибок, веб-слой и слой доступа к данным.
* Покрытие сервисного слоя — 100 % при требуемых 70–80 %, весь проект — ≈ 99 %.
* Тесты изолированы от рабочей базы: `mvn test` можно запускать в любой момент,
  данные магазина не затрагиваются.
* Отчёт о покрытии формируется автоматически (`mvn clean verify`),
  тексты ошибок и сообщений проверяются точно, поэтому тесты защищают
  не только от «паданий», но и от изменения поведения интерфейса.

## 6. Учебно-методическое пособие

К материалам курсовой работы подготовлено **учебно-методическое пособие** —
книга-учебник по устройству интернет-магазина:

📖 [`docs/book/README.md`](book/README.md) — «Flower Store: учебник по
устройству интернет-магазина», 13 глав.

**Назначение.** Книга предназначена для читателя, не имеющего опыта
программирования. Она позволяет разобрать проект «изнутри»: что делает
программа, как взаимодействуют компоненты и что применялось при написании
каждого файла.

**Структура пособия:**

| Блок | Главы | Содержание |
|------|-------|------------|
| Введение | 1–2 | сценарий работы магазина и словарь новичка (Java, HTTP, HTML, JSON, сессия) |
| Теория | 3–4 | устройство Spring Boot и работа с базой данных через JPA |
| Разбор проекта | 5–9 | архитектура, модель данных, сервисный слой, веб-слой, фронтенд |
| Тестирование | 10 | JUnit 5, AssertJ, Mockito, `@WebMvcTest`, `@DataJpaTest`, JaCoCo, TDD |
| Практика | 11–13 | запуск у себя, типичные проблемы, итоги и задания для самостоятельной работы |

**Особенности.**

* Весь код в книге процитирован из данного проекта — расхождений между
  описанием и реальным кодом нет.
* Каждая глава завершается блоками «Главное из главы» и «Вопросы для
  самопроверки», что позволяет использовать пособие для самоконтроля.
* Глава 12 собрана из реальных ошибок, возникавших при разработке и
  отладке проекта, — она служит справочником диагностики.
* Глава 13 содержит карту знаний, разбор известных ограничений проекта и
  пять уровней заданий для самостоятельной работы (от разбора архитектуры
  до написания собственного магазина).

Пособие может использоваться как при первичном разборе проекта, так и при
подготовке к защите — в качестве справочника по устройству приложения.
