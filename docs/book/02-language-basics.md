# Глава 2. Словарь новичка

> **Что мы уже знаем:** программа продаёт цветы, у неё есть покупатели,
> администратор, корзина и склад (глава 1). Теперь нужен словарь, чтобы
> понимать, что написано в файлах проекта.

Глава большая, но это **единственная** глава про «общие знания». Дальше
специальных терминов будет меньше — всё остальное мы объясним на примерах.

---

## 2.1. Как вообще работает веб-приложение

### Клиент и сервер

Представьте ресторан. Вы (гость) — **клиент**. Официант (или терминал) —
**посредник**. Кухня — **сервер**: она готовит блюда. Заказ уходит на кухню,
блюдо возвращается к вам.

В веб-приложении всё похоже, только посредник — браузер:

```
  [Браузер]  ──── запрос (HTTP) ────►  [Сервер: Java + Spring Boot]
      ▲                                          │
      └────────── ответ (HTML/JSON) ─────────────┘
```

* **Браузер** (Chrome, Firefox) — программа на компьютере пользователя. Она
  умеет показывать страницы и отправлять запросы серверу.
* **Сервер** — программа на нашем компьютере (или на сервере хостинга). Это
  наш Spring Boot-проект. Он слушает порт `8080`.
* **HTTP** — «язык», на котором они договариваются. У запроса есть **метод**
  (что сделать) и **адрес** (с чем), у ответа — **код** (как получилось) и
  **тело** (данные).

### Что означает адрес

```
http://localhost:8080/cart/add?productId=7
└──┬──┘ └─┬─┘ └─┬─┘ └──────┬──────┘ └───┬──┘
протокол  хост  порт  путь             параметры
```

* `http://` — протокол (правило, по которому идёт обмен).
* `localhost` — «этот же компьютер». Так тестируют программу локально.
* `8080` — порт: «дверь», на которой сервер ждёт посетителей. Порт 80 — для
  обычных сайтов, 8080 — чтобы не спорить с другими программами.
* `/cart/add` — **путь**: какое действие выполнить. В проекте это
  соответствует аннотации `@PostMapping("/cart/add")`.
* `?productId=7` — **параметры запроса**: дополнительные значения.

### Методы HTTP, которые встречаются в проекте

| Метод | Что означает | Пример в проекте |
|-------|-------------|-------------------|
| `GET` | «покажи» | `GET /api/products` — дай список товаров |
| `POST` | «сделай» | `POST /cart/add` — добавь товар в корзину |

### Коды ответа (HTTP-статусы)

Трёхзначное число в ответе. Самые важные для нас:

| Код | Значение | Когда в проекте |
|-----|----------|-----------------|
| `200` | Хорошо | `/api/products` вернул список |
| `204` | Нет содержимого | `/api/auth/me` для гостя (данных нет, но ошибки нет) |
| `302` / `303` | Перенаправь меня | после добавления в корзину — на `/cart.html` |
| `400` | Плохой запрос | пустое количество, отрицательная цена |
| `401` | Не авторизован | не вошёл |
| `403` | Запрещено | вошёл, но не админ |
| `404` | Не найдено | нет такого товара |
| `409` | Конфликт | не хватает остатка, недопустимый переход статуса |
| `500` | Ошибка сервера | непредвиденный сбой (в проекте стараемся не допускать) |

Запомните просто: **4xx — виноват клиент** (он прислал не то или не вошёл),
**5xx — виноват сервер** (у нас в проекте их быть не должно).

## 2.2. HTML, CSS и JavaScript — три языка фронтенда

Фронтенд (то, что видит пользователь) в нашем проекте — **статические файлы**,
без фреймворков и сборщиков. Это сознательное решение: весь учебный смысл
сосредоточен на сервере.

| Файл | Зачем |
|------|-------|
| `index.html`, `catalog.html`, … | **HTML** — «скелет» страницы: заголовки, кнопки, формы |
| `css/style.css` | **CSS** — внешний вид: цвета, отступы, шрифты |
| `js/common.js`, `js/layout.js`, `js/pages.js` | **JavaScript** — поведение: подгрузить данные, нарисовать каталог |

### Что такое HTML-форма и зачем она нужна

```html
<form method="post" action="/cart/add">
    <input type="hidden" name="productId" value="7">
    <button class="btn">В корзину</button>
</form>
```

Это **форма**: браузер сам соберёт значения полей и отправит их серверу методом
`POST` на адрес `/cart/add`. На сервере за этот адрес отвечает метод:

```java
@PostMapping("/cart/add")
public String addToCart(@RequestParam Long productId, ...)
```

Здесь `@RequestParam Long productId` говорит: «возьми из запроса параметр
с именем `productId` и преврати в число `Long`». Если клиент пришлёт не число —
сервер вернёт ошибку `400`.

Форма с `method="post"` и `type="hidden"` — важный приём: скрытое поле не видно
пользователю, но сервер его получает. Так в корзину передаётся `productId`,
а в админке — `id` редактируемого товара.

### JavaScript в проекте: три файла

* **`common.js`** — мелкие помощники: `$('id')` (найти элемент страницы),
  `esc(text)` (экранировать текст, чтобы чужой HTML не попал в страницу),
  `money(n)` (отформатировать цену), `get(url)` (спросить сервер).
* **`layout.js`** — общая шапка и подвал для всех страниц: проверяет, кто вошёл,
  рисует меню и счётчик товаров в корзине, показывает всплывающее сообщение.
* **`pages.js`** — логика каждой страницы: каталог, корзина, оформление заказа,
  личный кабинет, админка. Каждая функция соответствует одной странице.

### Как страница получает данные: `fetch`

```javascript
const products = await get('/api/products');
```

`fetch` — встроенная в браузер функция: «сходи по этому адресу и принеси ответ».
Ответ приходит в формате **JSON** — текстовый формат обмена данными:

```json
[ { "id": 1, "name": "Роза красная, 60 см", "price": 4.50, "stock": 100, "visible": true } ]
```

JavaScript превращает такой текст в готовые объекты, и страница рисует карточки
товаров.

## 2.3. Минимальный словарь Java

### Класс, объект, поле, метод

Java — **объектно-ориентированный** язык. Это значит, что программа состоит из
объектов, каждый из которых отвечает за что-то одно.

**Класс** — чертёж. **Объект (экземпляр)** — изделие по этому чертежу.

```java
@Entity
public class Product {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) public Long id;
    @Column(nullable = false) public String name;
    @Column(nullable = false, precision = 10, scale = 2) public BigDecimal price;
    public int stock;
    public boolean visible = true;
}
```

* `class Product` — объявление класса. Класс `Product` описывает товар.
* `public Long id;` — **поле**: данные, которые есть у каждого товара.
  `public` — «доступно всем», `Long` — тип (целое число «длинного» размера),
  `id` — имя.
* `public boolean visible = true;` — у поля может быть **значение по
  умолчанию**: новый товар сразу «виден».
* `public Product getCategoryId() { ... }` — **метод**: действие, которое умеет
  выполнять объект.

**Ключевое отличие Java от JavaScript (о котором часто путаются):** в Java
каждая переменная имеет **тип**, и тип объявляется явно. `Long id;` — это
«целое число, возможно null». `int stock;` — «целое число, точно не null».

### Типы, которые встретятся в проекте

| Тип | Что это | Пример в проекте |
|-----|---------|------------------|
| `int` | целое число | `stock`, `qty` |
| `long` / `Long` | большое целое число | `id` товара, `userId` |
| `double` | число с дробной частью | (не используется — см. ниже) |
| `boolean` | «да» или «нет» | `visible` |
| `String` | строка (текст) | `name`, `email`, `status` |
| `BigDecimal` | «точное» денежное число | `price`, `total` |
| `LocalDateTime` | дата и время | `createdAt` |
| `List<T>` | список элементов типа `T` | `List<Order>`, `List<OrderItem>` |
| `Map<K, V>` | «словарь»: ключ → значение | `Map<Long, Integer>` — корзина |

#### Почему деньги — это `BigDecimal`, а не `double`

`double` хранит число приблизительно (как 1/3 = 0.3333...). Если сложить
`0.1 + 0.2`, получится `0.30000000000000004`. Для цветов за 4.50 Br это
недопустимо. `BigDecimal` хранит десятичную дробь точно: `4.50` — это ровно
`4.50`.

Но `BigDecimal` нельзя складывать с обычным числом `int` напрямую. Отсюда
странноватая, но правильная строка в проекте:

```java
BigDecimal sum = product.price.multiply(BigDecimal.valueOf(qty));
```

`BigDecimal.valueOf(qty)` — «преврати целое число `qty` в `BigDecimal`», чтобы
можно было умножить.

### `package` и `import` — папки и «подключение»

```java
package shop.service;                       // «я лежу в папке shop/service»
import shop.repository.ProductRepo;         // «мне нужен класс из shop/repository»
import static shop.exception.ApiException.check;  // «мне нужна статическая функция check»
```

Физически `package shop.service;` означает, что файл лежит в
`src/main/java/shop/service/`. Имя пакета — это и имя папки, и часть
полного имени класса: `shop.service.CartService`.

`import static ... .check` — необычная, но удобная вещь: позволяет писать
`check(условие, "Текст")` вместо `ApiException.check(условие, "Текст")`.

### Аннотации

Аннотация — это **пометка** в коде, которую читает фреймворк. Синтаксис
`@ЧтоТо(параметры)`. Сама по себе аннотация ничего не делает — она говорит
Spring Boot: «считай меня вот таким».

| Аннотация | Смысл |
|-----------|-------|
| `@Entity` | этот класс — таблица в базе |
| `@Service` | этот класс — сервис (бизнес-логика) |
| `@Repository` | этот класс — доступ к данным |
| `@RestController` | этот класс — веб-контроллер, отдающий JSON |
| `@Controller` | этот класс — веб-контроллер, отдающий страницы/редиректы |
| `@Component` | «это компонент Spring» (общее слово) |
| `@Bean` | «этот объект создай и положи в контейнер» |
| `@Transactional` | «выполни метод целиком, либо не выполняй вовсе» |
| `@GetMapping("/api/products")` | «на GET по адресу `/api/products` отвечай этим методом» |
| `@PostMapping("/cart/add")` | «на POST по адресу `/cart/add` отвечай этим методом» |

### Конструктор и внедрение зависимостей

```java
private final ProductRepo products;

public CartService(ProductRepo products) {
    this.products = products;
}
```

* **Конструктор** — специальный метод, который вызывается при создании объекта.
  Он «принимает» то, что объекту нужно для работы.
* `final` — поле нельзя переприсвоить после создания. Это гарантирует, что
  сервис всегда работает с тем репозиторием, который ему дали.
* `this.products = products;` — «в поле объекта положи то, что пришло в
  конструктор».

Кто вызывает конструктор? **Spring.** Он сам создаёт все нужные объекты и
подставляет зависимости. Никто в коде не пишет `new CartService(...)` — это
и есть «внедрение зависимостей» (Dependency Injection, DI). Подробности — в
главе 3.

### Перечисление (`enum`) — «одно из конечного числа значений»

```java
public enum Role {
    USER, ADMIN
}
```

Роль пользователя может быть только `USER` или `ADMIN`. Никаких других
значений быть не может — компилятор не даст написать `Role.USER1`.

### `record` — «неизменяемая пара данных»

```java
public record OrderData(String customerName, String email, String phone,
                         String address, String payment) {}
```

`record` — сокращение для класса, который просто хранит несколько значений и
ничего больше. У него автоматически есть конструктор и методы-получатели:
`data.customerName()`, `data.email()`. Обратите внимание: **со скобками**,
в отличие от обычного поля `user.name`.

Когда применять `record`? Когда это «данные, которые передали и забыли»:
входные данные формы, «представление корзины» (позиции + итог).

### Исключения

Исключение — это «ошибка, которая летит вверх по стеку вызовов».

```java
if (wanted > product.stock)
    throw ApiException.conflict("Недостаточно на складе: доступно " + product.stock + " шт.");
```

`throw` — «бросить». Что происходит дальше:

1. Текущий метод прерывается.
2. Исключение летит вверх, пока его не поймают (`catch`) или пока не дойдёт до
   специального обработчика.
3. В нашем проекте ловит его `ErrorHandler` (глава 8) и превращает в
   понятный ответ с кодом 409.

В проекте есть **свой** тип исключения — `ApiException`, у которого есть поле
`status` (HTTP-код). Это удобно: проверка «условие нарушено» превращается в
одну строку с кодом.

### Коллекции

| Тип | Что это | Пример |
|-----|---------|--------|
| `List<T>` | упорядоченный список, возможны повторы | позиции заказа |
| `Map<K,V>` | «словарь»: ключ → значение | корзина `id товара → количество` |
| `Set<T>` | множество: без повторов | (в тестах) |

В проекте корзина — это `Map<Long, Integer>`: по идентификатору товара лежит
количество. Одна позиция — одна запись, сколько бы раз товар ни добавляли.
Именно поэтому корзина «помнит» товар, который добавили дважды, как одну
позицию с количеством 2.

### Методы интерфейса `Optional`

```java
public Optional<Product> findById(Long id);
```

`Optional` — «ящик, в котором может лежать значение, а может и не лежать».
Вместо `null` (которое легко не проверить и получить «NullPointerException»)
вы получаете ящик, который нужно сначала открыть:

```java
products.findById(id)
        .filter(p -> p.visible)
        .orElseThrow(() -> ApiException.notFound(ApiException.PRODUCT_NOT_FOUND));
```

Читается как предложение: «найди товар → оставь, только если он видимый →
если ничего не осталось — выброси ошибку 404».

### Лямбда-выражения

`->` — это короткая запись «функции без имени».

```java
.filter(p -> p.visible)             // «оставь, если p видимый»
cart.items.reduce((sum, item) -> sum + item.qty, 0)   // «сложи количества»
```

Читается: «для каждого `p` проверь `p.visible`». В проекте их несколько
десятков — и все понятны.

### `var` и `stream`

```java
Stream<Product> stream = products.findByVisibleTrue().stream();
stream = stream.filter(p -> p.category != null && categoryId.equals(p.category.id));
stream = stream.sorted(Comparator.comparing((Product p) -> p.price));
return stream.toList();
```

`stream` — это «конвейер»: данные текут по нему, на каждом шаге
(`filter`, `sorted`) что-то с ними происходит, в конце `toList()` собирает
результат. Читается почти как обычный текст.

## 2.4. Сессия и «кто я»

Сервер должен помнить, кто вошёл. Для этого у каждого посетителя есть
**сессия** — коробка с его личными данными на стороне сервера. Браузер получает
номер сессии в cookie и при каждом запросе передаёт его обратно.

Что лежит в сессии в нашем проекте:

| Ключ | Что хранится | Кто читает |
|------|--------------|------------|
| `"userId"` | идентификатор вошедшего пользователя | `AuthService` |
| `"cart"` | корзина: `Map<Long, Integer>` | `CartService` |

Ключ `"userId"` объявлен как константа в `AuthService`:

```java
public static final String USER_ID = "userId";
```

`public static final` — «общее неизменяемое значение». Имя в верхнем регистре —
соглашение Java для констант. Почему это важно для тестов: тесты обращаются
к сессии **по этому имени**, как и делает настоящий сервис. Если бы имя было
зашито в трёх местах разными буквами, тесты проверяли бы не то, что работает
в приложении.

## 2.5. Тестирование — термины, которые встретятся

| Термин | Значение |
|--------|----------|
| **Тест** | программа, которая проверяет другую программу |
| **Юнит-тест (модульный тест)** | проверка одной маленькой части (класса) целиком |
| **Мок (mock)** | «подделка»: объект-заглушка вместо настоящего |
| **Стаб (заглушка)** | общее название подделок; мок — тот, который ещё и запоминает вызовы |
| **Assertion (проверка)** | утверждение «это должно быть так» |
| **Покрытие кода** | какая доля строк программы выполнилась во время тестов |
| **TDD** | разработка через тесты: сначала пишут тест, потом код |

Подробно — в главе 10.

## 2.6. Главное из главы

1. Браузер и сервер общаются по HTTP: запрос → ответ, у ответа есть код.
2. Фронтенд — статические HTML + CSS + JS; данные он берёт у сервера через
   `fetch` в формате JSON.
3. Java: класс — чертёж, объект — изделие; поля хранят данные, методы
   выполняют действия; тип объявляется явно.
4. Деньги храним в `BigDecimal`, потому что `double` умеет ошибаться.
5. Spring создаёт объекты сам и подставляет зависимости — «внедрение
   зависимостей».
6. Сессия — серверная память о конкретном посетителе: кто вошёл и что в
   корзине.
7. Исключение — управляемый способ сообщить «так делать нельзя».

**Вопросы для самопроверки**

1. Чем `int` отличается от `Integer`? А `long` от `Long`?
2. Почему для цены выбран `BigDecimal`, а не `double`?
3. Что означает `@RequestParam Long productId` в методе контроллера?
4. Что произойдёт, если в HTML-форме написать `name="prodactId"` вместо
   `name="productId"`?
5. Зачем в проекте константа `AuthService.USER_ID`, а не строка `"userId"`
   прямо в коде?
